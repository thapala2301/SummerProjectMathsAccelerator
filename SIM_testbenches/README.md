# SIM_testbenches — Simulation and Verification

Two types of testbench: SystemVerilog unit tests (run with Icarus/Questa) and Verilator C++ PPM render tests that run the full RTL pipeline and write a pixel-accurate image.

---

## SystemVerilog testbenches (`testbenches/`)

### `tb_fp_lib.sv`

Tests every FP27 arithmetic module: `fp_add`, `fp_sub`, `fp_mul`, `fp_isqrt`, `fp_length`, `fp_normalize`, `fp_abs`, `fp_max`, `fp_min`. Inputs and expected outputs are loaded from hex files, the DUT is clocked, and results are compared against golden values within a small tolerance.

Test vectors in `test_vectors.hex` — generated by `gen_vectors.py` using Python's `float` as the reference.

### `tb_march_core.sv`

Feeds known rays into `march_core` with a mock `scene_sdf` (sphere) and checks that pixels either hit or miss correctly, and that `pix_id`, `iter`, and position outputs are cycle-aligned.

### `tb_scene_sdf.sv`

Tests the scene SDF modules directly. For each of a set of known 3D points, checks that the returned signed distance has the correct sign (positive outside, negative inside) and is within a reasonable bound.

Test vectors in `test_vectors_scene_sdf.hex`.

### `tb_analytic_sdf.sv`

Broader coverage: tests many analytic SDF shapes — sphere, torus, box, capsule, gyroid, octahedron, pyramid, and more — each against Python-generated golden vectors. One hex file per shape:

```
test_vectors_sdf_sphere.hex
test_vectors_sdf_torus.hex
test_vectors_sdf_box.hex
test_vectors_sdf_capsule.hex
test_vectors_sdf_gyroid.hex
test_vectors_sdf_octahedron.hex
test_vectors_sdf_twisted_torus.hex
test_vectors_sdf_mandelbulb.hex   ← research only
...
```

### `tb_sdf_term.sv`

Tests individual SDF operator terms (domain operations like twist, bend, elongate).

### Running the SV tests

```bash
# Icarus Verilog
iverilog -g2012 -o sim tb_fp_lib.sv ../RTL/FP_Lib/*.v && ./sim

# Or use the PowerShell script (Windows):
powershell -File run_all_tests.ps1
```

## Generating test vectors

```bash
cd testbenches
python3 gen_vectors.py                # FP lib vectors
python3 gen_vectors_analytic.py       # analytic SDF vectors (all shapes)
python3 gen_vectors_scene_sdf.py      # full scene SDF vectors
python3 gen_vectors_sdf_term.py       # SDF domain operator vectors
```

Requires Python 3 + numpy. Uses Python's `float` (IEEE 754 double) as the reference — results are then quantised to FP27 for comparison. Tolerance is set to account for the 18-bit mantissa precision gap.

## Verilator C++ PPM testbenches

These run the complete RTL pipeline through Verilator and write a PPM image that reflects exactly what the hardware would produce. Use these to verify a new scene before committing to a Vivado build.

The Makefiles and C++ source live in the `SIM_testbenches/` root (alongside this README).

### Menger sponge

```bash
make menger_ppm
open menger.ppm
```

Runs the full pipeline with `menger_sdf`, renders a frame at simulation resolution, and writes `menger.ppm`.

### Mandelbox

```bash
make mandelbox_ppm
open mandelbox.ppm
```

Same, but with `mandelbox.sv`. Also runs 9 inside/outside spot checks and prints PASS/FAIL for each:

- Origin (0,0,0): expect SDF ∈ [0.000, 0.010]
- Inside sphere (0,0,−1): expect SDF ∈ [0.000, 0.500]
- Inside sphere (1,0,−1): expect SDF ∈ [0.000, 0.800]
- Centre slice (0,0,−2): expect SDF ∈ [0.000, 1.700]
- Near bounding sphere (2.5,0,0): expect SDF ∈ [0.000, 2.000]
- (+ 4 more)

All 9 pass as of June 2026.

## Pipeline latency and warm-up

The Verilator testbenches set `PIPELINE_LAT = SCENE_CORE_LAT − 1` (Verilator's off-by-one convention vs. RTL). They drive a warm-up of `PIPELINE_LAT + a few` cycles before sampling outputs. Getting `PIPELINE_LAT` wrong causes the sim to sample outputs one or more cycles too early, producing a shifted/corrupt image.

Current values:
- Menger: `PIPELINE_LAT = 100` (SCENE_CORE_LAT = 101 in RTL)
- Mandelbox: `PIPELINE_LAT = 233` (SCENE_CORE_LAT = 234 in RTL)
